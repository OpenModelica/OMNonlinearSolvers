# Contributing

## Setup

Install a stable Rust toolchain with [rustup][rustup].

### Git hook

The repository ships a pre-commit hook in [.githooks/](.githooks/) that runs on
every commit. For staged Rust files it adds a missing license header, updates an
outdated copyright year and formats the file with `rustfmt`. Staged Markdown
files it fixes with `markdownlint-cli2`, if Node.js is installed. Enable it once
after cloning:

```sh
git config core.hooksPath .githooks
```

This only changes the configuration of your local clone. To disable the hook
again, run `git config --unset core.hooksPath`.

If a staged file also has unstaged changes, the hook only checks it, so that the
unstaged changes don't end up in the commit. When such a file has no valid
license header or is not formatted, the commit is aborted. Run
`.ci/check_license.py --fix` and `cargo fmt`, stage the result and commit again.
The commit is also aborted for Markdown issues `markdownlint-cli2` can't fix
itself, like a line that is too long.

## Formatting and Linting

The code uses the default `rustfmt` style and must be free of compiler and
Clippy warnings. CI fails on any warning, check locally with:

```sh
cargo fmt
cargo clippy --workspace --all-targets -- -D warnings
```

The Markdown files are checked with [markdownlint-cli2][markdownlint-cli2],
configured in [.markdownlint-cli2.yaml](.markdownlint-cli2.yaml): lines of
prose are at most 80 characters. With Node.js installed, check them with:

```sh
npx markdownlint-cli2
```

## License Headers

Every Rust file must start with the OpenModelica Run-Time System license header,
with the current year in the copyright line. Add missing headers and update the
year with:

```sh
.ci/check_license.py --fix
```

Without `--fix`, the script only checks the files. Pass file names to check only
those files instead of all Rust files in the repository.

## Coverage

Coverage is measured with [cargo-llvm-cov][cargo-llvm-cov]. Install it once:

```sh
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov --locked
```

Run the tests with coverage and open the HTML report:

```sh
cargo llvm-cov --open
```

## Mutation testing

[cargo-mutants][cargo-mutants] changes the code in small ways, one mutant at
a time, and checks that a test fails for each of them. Install it once and
run it for one file or for all of them:

```sh
cargo install cargo-mutants --locked
cargo mutants -f openmodelica_nls_model/src/scaling.rs
cargo mutants --jobs 4
```

A full run takes about 20 minutes with 4 jobs. The results are in
`mutants.out/`: `missed.txt` lists the mutants no test caught. Each mutant is
tested with the tests of the whole workspace, mutants that can't change the
behaviour are excluded, both configured in
[.cargo/mutants.toml](.cargo/mutants.toml). Swaps of `<` and `<=` on floats
are expected to be missed, they only differ for a value equal to a
tolerance.

## Documentation

Build the documentation, including private items, and open it in the browser:

```sh
cargo doc --no-deps --document-private-items --open
```

## C Header

The C interface of `openmodelica_homotopy_capi` is described by the header
[openmodelica_homotopy_capi/include/openmodelica_homotopy_capi.h](openmodelica_homotopy_capi/include/openmodelica_homotopy_capi.h).
It is generated by [cbindgen][cbindgen] from the exported items of the crate:
the `#[unsafe(no_mangle)] extern "C"` functions, the `#[repr(C)]` types and the
`pub const` values, with their doc comments. `cbindgen` is a build-dependency,
it needn't be installed.

* The build script
  [openmodelica_homotopy_capi/build.rs](openmodelica_homotopy_capi/build.rs)
  writes the header whenever `openmodelica_homotopy_capi` is built and a file
  in `openmodelica_homotopy_capi/src/` or
  [openmodelica_homotopy_capi/cbindgen.toml](openmodelica_homotopy_capi/cbindgen.toml)
  changed:

  ```sh
  cargo build -p openmodelica_homotopy_capi
  ```

* Don't edit the header by hand, the next build overwrites it. Change the Rust
  code or the configuration in `cbindgen.toml` instead, for example the naming
  of the enum variants.
* Commit the header together with the change of the exports. CI builds the
  crate and fails if the generated header differs from the committed one.
* Only items reachable from the crate root are exported, so new public items
  must be re-exported in
  [openmodelica_homotopy_capi/src/lib.rs](openmodelica_homotopy_capi/src/lib.rs).
  A type that C only handles by pointer, like `HomSolver`, has no `#[repr(C)]`
  and becomes an opaque `typedef struct`.

`cargo test -p openmodelica_homotopy_capi` also compiles a small C program
against the header with `cc`, if a C compiler is installed.

### C tests

[openmodelica_homotopy_capi/tests/c](openmodelica_homotopy_capi/tests/c) uses
the interface from C, as a host does: a smoke test of its functions and the C
example of the [README](README.md), which CMake extracts from the README so
that it stays valid. They need CMake and a C compiler. The CMake build builds
the static library with cargo first and links it like a C host does:

```sh
cmake -S . -B build_c
cmake --build build_c
ctest --test-dir build_c --output-on-failure
```

Keep the README example a complete program, with a single `c` code block in
the README.

## Continuous Integration

Every pull request and push to `main` runs [ci.yml](.github/workflows/ci.yml),
which checks the formatting, the license headers and the Markdown files, runs
Clippy with warnings as errors, builds the crate, checks that the C header is up
to date, runs the tests, runs the C tests, and builds the documentation. The
coverage job prints a summary on the run's page and uploads the HTML report as
the `coverage` artifact.

[mutants.yml](.github/workflows/mutants.yml) runs cargo-mutants: on a pull
request for the mutants in its changes, every Monday and on demand for all of
them. It lists the missed mutants on the run's page and uploads `mutants.out`
as an artifact, but doesn't fail for missed mutants.
